# Adopt React Testing Library with Vitest for Component and Unit Testing: Component Tests Use

These rules are ALWAYS ACTIVE for all React components, custom hooks, utility functions, and state management stores in the codebase.

### Rules

- **R-RTL-001** MUST: Component tests MUST use React Testing Library for rendering and interaction testing, following user-centric testing patterns.
- **R-RTL-002** MUST: All React components in src/components, src/features/**/components, and all custom hooks in src/hooks MUST have corresponding .test.tsx or .test.ts files co-located with source files.
- **R-RTL-003** MUST: All utility functions in src/lib and state management stores in src/stores MUST have corresponding .test.ts files with at least one test case.
- **R-RTL-004** MUST: Test files MUST use the naming convention .test.tsx for components and .test.ts for utilities and hooks.
- **R-RTL-005** MUST: The test suite MUST execute successfully with vitest run command and all tests MUST pass before code can be merged.
- **R-RTL-006** MUST: Package.json MUST contain both @testing-library/react and vitest as dependencies.
- **R-RTL-007** SHOULD: Tests SHOULD focus on user behavior rather than implementation details to ensure maintainability and resilience.
- **R-RTL-008** SHOULD: Shared test utilities and custom render functions (e.g., renderWithProviders) SHOULD be created to handle common setup like Redux stores, React Router, and theme providers.

### Verify

```bash
# Check for missing test files for components and utilities
find src -type f \( -name '*.tsx' -o -name '*.ts' \) ! -name '*.test.*' ! -name '*.spec.*' -exec sh -c 'test -f "${1%.tsx}.test.tsx" -o -f "${1%.ts}.test.ts" || echo "Missing test: $1"' _ {} \;

# Verify testing dependencies are installed
grep -q "@testing-library/react" package.json && grep -q "vitest" package.json && echo "Testing dependencies found"

# Run test suite and generate coverage report
vitest run --coverage --reporter=json --reporter=text

# Count test files
grep -l "describe\|test\|it" src/**/*.test.{ts,tsx} 2>/dev/null | wc -l
```

**Accept when:**
- All component files (.tsx) have corresponding .test.tsx files with at least one test case
- All utility and hook files (.ts) have corresponding .test.ts files with at least one test case
- Test suite executes successfully with vitest run command and all tests pass
- Package.json contains both @testing-library/react and vitest as dependencies
- CI/CD pipeline includes test execution step that blocks merges on test failures
- Code coverage reports are generated by Vitest and reviewed during pull request process

<enforcement>
Claude Code MUST NOT skip or defer verification. Pull requests without corresponding tests are blocked from merging. CI/CD pipeline fails if test suite does not pass or coverage drops below threshold. Automated comments on pull requests identify missing test files. Tech lead review is required for any exceptions to testing requirements.
</enforcement>
