# Adopt React Testing Library with Vitest for Component and Unit Testing: Test Files Executed

These rules are ALWAYS ACTIVE for all React components, custom hooks, utility functions, and state management stores in the codebase that require test coverage.

### Rules

- **R-TEST-001** MUST: Test files MUST be executed using Vitest as the test runner and assertion library.
- **R-TEST-002** MUST: All React components in src/components, src/features/**/components, and form/dialog components MUST have corresponding .test.tsx files with at least one test case.
- **R-TEST-003** MUST: All custom hooks in src/hooks MUST have corresponding .test.ts files with at least one test case.
- **R-TEST-004** MUST: All utility functions in src/lib MUST have corresponding .test.ts files with at least one test case.
- **R-TEST-005** MUST: All state management stores in src/stores MUST have corresponding .test.ts files with at least one test case.
- **R-TEST-006** MUST: Test files MUST be co-located with source files using .test.tsx (for components) and .test.ts (for utilities/hooks) naming conventions.
- **R-TEST-007** MUST: The test suite MUST execute successfully with the `vitest run` command and all tests MUST pass.
- **R-TEST-008** MUST: Package.json MUST contain both @testing-library/react and vitest as dependencies.
- **R-TEST-009** MUST: CI/CD pipeline MUST include a test execution step that blocks merges on test failures or coverage drops below configured thresholds.
- **R-TEST-010** SHOULD: Tests SHOULD focus on user behavior rather than implementation details using React Testing Library best practices.
- **R-TEST-011** MAY: Prototype or spike code explicitly marked as experimental MAY be exempted from test requirements (EXC-001).
- **R-TEST-012** MAY: Pure presentational components with no logic (props pass-through only) MAY be exempted from test requirements (EXC-002).

### Verify

```bash
# Check for missing test files for components and utilities
find src -type f \( -name '*.tsx' -o -name '*.ts' \) ! -name '*.test.*' ! -name '*.spec.*' -exec sh -c 'test -f "${1%.tsx}.test.tsx" -o -f "${1%.ts}.test.ts" || echo "Missing test: $1"' _ {} \;

# Verify testing dependencies are installed
grep -q "@testing-library/react" package.json && grep -q "vitest" package.json && echo "Testing dependencies found"

# Run test suite and generate coverage report
vitest run --coverage --reporter=json --reporter=text

# Count test files in the codebase
grep -l "describe\|test\|it" src/**/*.test.{ts,tsx} 2>/dev/null | wc -l
```

**Accept when:**
- All component files (.tsx) have corresponding .test.tsx files with at least one test case
- All utility and hook files (.ts) have corresponding .test.ts files with at least one test case
- Test suite executes successfully with `vitest run` command and all tests pass
- Package.json contains both @testing-library/react and vitest as dependencies
- CI/CD pipeline includes test execution step that blocks merges on test failures
- Code coverage reports are generated by Vitest and reviewed during pull request process

Claude Code MUST NOT skip or defer verification of these rules. All test files MUST be executed using Vitest, and CI/CD pipeline verification is mandatory before code merge.
</enforcement>
